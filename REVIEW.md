## Looked at and judged fine
* `load_dotenv()` uses `override=False`, so real environment variables already win over `.env` (required by the contract). Kept.
* Plain `def` endpoints with the synchronous PyMongo driver: FastAPI runs them in a thread pool, so the event loop is not blocked, and `MongoClient` is thread-safe. Kept.
* `MongoClient` is created at import time: it connects lazily, so import does not fail when MongoDB is down.
* `doc.pop("_id")` after `insert_one`: correct idea (insert_one adds `_id` to the dict); I build the response before inserting instead.
* Indexes: `employees` - unique `emp_code`, `(department, emp_code)`, `(joined_on)`. `attendance_logs` - unique `(emp_code, date)`, `(date desc, emp_code)`, `(status, date desc, emp_code)`, `(emp_code, punch_in desc)`. All used by query patterns, verified by `explain` with `executionStats` (IXSCAN, no COLLSCAN).
* Rounding: `_half_up_div` helper for integer half-up division used everywhere (R8). `work_hours_cents` uses integer arithmetic for half-up rounding of hours (R4).
* Truncation: `instant_from_ms` truncates to whole seconds before any calculation/storage (R1).
* History: Only manual corrections (PATCH) write to history. Punch-in/out never write to it. Each entry has `at` (epoch ms), `by`, `reason`, `changes` (only changed fields). Entries never modified/removed.
